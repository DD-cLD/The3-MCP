**RATIFIED 2026-07-23 (Dave, three calls).** The corpus is shelved **by role**, with the programmer as the spine.

**MISSION RULING (Dave, the reason the partition exists):** the remaining job is *being a good MA3 programmer from the Claude interface* — portable enough to be handed a design package from ANY show and program it. The design hall is largely done; beatgrid/cLD MAker is built and closed; show-creation is not the programmer's job. Dave's framing for urgency: *"If we don't create the system now, it just drifts back away."*

**The three calls:**

1. **SPLIT INDEX FILES.** `concepts/INDEX.md` = programmer + operational, **the only auto-load**. `concepts/INDEX_DESIGN.md` and `concepts/INDEX_TOOLS.md` are summoned only.
2. **SHOW PACKETS.** Show-specific facts distill to per-show `<SHOW>_SHOW_PACKET` docs. The tourshow packet boots alongside the spine while the tour is active; it is the **`LD.md` seed**. cLD writes packets; the librarian only flags `→packet` findings.
3. **Sequencing:** taxonomy + filing law land immediately; the heavy partition run (INBOX mega-digest + role backfill + index rebuild + README boot-chain update + cold-boot drill) is a separate, dedicated session.

**Role table** (full version in `LIBRARIAN.md` v0.2): `programmer` = the mechanical toolkit · `operational` = how cLD runs itself · `design` = WHAT/WHY · `tools` = built engineering · `historical` = past-rig facts. Era tags (`coachella` / `tourshow` / untagged) stay orthogonal to role. A finding files to exactly ONE role index; dual-nature concepts shelve where they are *retrieved for use*, with a one-line cross-pointer allowed in the other. Bodies never move, never delete — **the partition is re-shelving, not pruning**.

**The knowledge cut that drives it (Dave, 2026-07-21, the STAR PRINCIPLE this implements):** split the pipeline by WHAT EACH SIDE KNOWS. Design side knows music/story/aesthetics plus programming *concepts*, and produces the idea-file. The programmer knows how to render the idea-file to the console and decides nothing aesthetic. Critically, the programmer does **NOT** carry "almost nothing" — it carries the **FULL MECHANICAL TOOLKIT**: connect/get inside the console, review the show file, export, import, CLI + MCP syntax, SaveShow + console-killer safety. What it does not carry is the design hall. See `idea-file-design-programmer-boundary-doctrine`.

**LIBRARIAN.md v0.2 filing law shipped with it (additive):** `role:` required on every concept touched · role→index filing table · **trigger-worded lines are law** (an index line missing its concept's retrieval triggers is a *filing defect* — the quote-miss lesson) · front-matter diet (run history → `LIBRARIAN_LOG.md`, index front-matter under ~15 lines) · librarian flags `→packet`, never writes packets · verification checklist grows a retrieval spot-check.

**[SUPERSEDED IN PART 2026-07-24 — see the spine ruling.]** The "INDEX.md is the auto-load" mechanism above was revised the next day: measurement showed `INDEX.md` cost ~16K tokens per session to *describe* knowledge that costs ~6× to simply *carry*, inside a 1M window. The programmer spine now **loads whole** and indexing is retained only for the summoned shelves. The role partition itself — the shelves, the filing law, the show-packet class, the mission ruling — is unchanged and remains in force; only the retrieval mechanism for the spine changed.
